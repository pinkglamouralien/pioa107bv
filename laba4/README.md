# Лабораторная работа №4: Работа с файлами (СУБД Ресторана)

## Описание проекта
Данный проект представляет собой систему управления базой данных ресторана. Главная цель текущей лабораторной работы - расширение объектно-ориентированной архитектуры за счет добавления файловых хранилищ с сохранением единого публичного интерфейса (применение принципов наследования и полиморфизма). Система позволяет управлять гостями, меню блюд и заказами.

## Реализованная архитектура
Проект спроектирован с использованием ООП и поддерживает три типа хранилищ данных:
1. **In-memory (`memory.py`)** - базовая реализация. Данные хранятся в оперативной памяти в виде объектов Python и теряются при завершении работы программы. Этот класс содержит всю основную бизнес-логику и служит родителем для остальных СУБД.
2. **JSON Database (`json_db.py`)** - файловая СУБД. Все сущности сериализуются и сохраняются в единый структурированный файл `data/restaurant.json`. Обеспечивает персистентность.
3. **CSV Database (`csv_db.py`)** - файловая СУБД в табличном формате. Данные логически разделены по независимым файлам (таблицам): `data/guests.csv`, `data/dishes.csv`, `data/orders.csv`.

Выбор конкретной реализации СУБД осуществляется пользователем в консольном меню при старте программы. Благодаря общему интерфейсу, код пользовательского интерфейса (`tui.py`) не требует изменений при добавлении новых форматов хранения.

## Функциональные возможности
- **CRUD-операции**: добавление, чтение, обновление и удаление записей для сущностей Гости, Блюда, Заказы.
- **Сортировка**: вывод списка гостей, отсортированного по имени.
- **Валидация**: защита от добавления дубликатов по ID, проверка на отрицательную цену блюд и нулевое/отрицательное количество порций в заказах.
- **Автосохранение**: все изменения при выборе файловых СУБД моментально и автоматически синхронизируются с жестким диском.

## Инструкция по запуску
Для корректной работы системы импортов, запуск необходимо производить строго из корневой директории проекта (там, где находится этот файл `README.md`).

Выполните команду в терминале:

```bash
python src/db/__main__.py
```

## Запуск авто-тестов
Система покрыта модульными тестами с использованием стандартной библиотеки `unittest`. Тесты проверяют как корректность работы бизнес-логики, так и сохранение данных на диске между запусками экземпляров программы.

Для запуска всех тестов выполните из корневой директории:

```bash
python -m unittest discover tests
```

## Проверка покрытия тестами

Установить пакет coverage:

```bash 
pip install coverage 
```

Запустить тесты с подсчётом покрытия:

```bash 
coverage run -m unittest discover tests 
```

Сформировать отчёт:

```bash 
coverage report
```
